# pair-wise-yf-56 网络安全事件响应作战室

## 源提示词摘要
值班人员接收告警，分析人员补充资产和影响范围，响应负责人批准隔离、封禁或恢复动作，法务和公关维护对外口径。系统展示实时事件时间线、子事件、审批、证据和责任人；高优先级动作双人确认，敏感内容按角色显示，并支持只读演示模式。

## 技术栈
Next.js 15 + TypeScript + App Router + shadcn/ui 本地组件 + Zustand + TanStack Query + React Hook Form + Zod + next-intl + date-fns + dnd-kit。

## 已实现闭环
- 主事件、子事件、处置动作和实时时间线。
- 子事件创建、动作审批、双人确认和执行状态流转。
- 角色权限控制、敏感内容遮蔽、只读演示模式。
- dnd-kit 调整处置优先级、TanStack Query 实时连接检查和 Zustand 持久化。

## 协同续作模型（lib/collab.ts + lib/store.ts）
系统不再用"后写覆盖"的对象合并，而是把审批、执行、事实变更、建子事件、排序统一建模为带全局唯一标识（opId）的**操作日志**，所有视图由日志确定性回放（reconcile）得出：

- **事实版本（rev）续作**：影响范围或处置阶段一旦变更，主事件 rev 递增；所有**尚未执行**的动作 rev 跟随推进、其旧版本审批立即作废并**退回待确认**；**已执行**的动作版本冻结、执行事实与全部审批审计记录原样保留。
- **审批账册**：审批是不可变记录，按 `(动作, 版本, 角色)` 去重——同一角色重复确认只算一次；两人几乎同时按同一版本提交时各自留一条有效审批（隔离动作仍需两名不同角色）。
- **旧事实不可执行**：执行/审批操作携带其依据的 rev，与动作当前 rev 不符即拒绝，按旧事实作出的决定不会被拿去执行。
- **断网发件箱**：断网（顶栏在线/断网开关模拟）期间操作进入本机发件箱并乐观显示（标"待同步"）；回网时先收齐其他端推进的历史，再把发件箱按 opId 幂等合并、按到达时刻对账——合得上的入历史，合不上（版本对不上、门槛不足、对象不存在等）的进入"协同与离线合并"卡片单独列出，可人工知悉归档。
- **多标签页协同**：同一浏览器多个标签页通过 storage 事件交换操作日志，提交前先并入对端最新操作，避免并发末位写入互相覆盖；角色与在线状态为每标签页本地态。
